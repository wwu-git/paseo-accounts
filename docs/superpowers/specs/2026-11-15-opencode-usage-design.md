# OpenCode 2 用量接入

按已确认的接入方案在独立 worktree 中实现。

通过 `opencode api experimental.usage.limits` 获取当前 location 的 Console 工作区 Go 三窗口用量。CLI 持有凭据；插件不导出凭据、不读取数据库、不直接请求云端。与直接请求官方 Go API 相比，这减少凭据处理和认证重复；本地 stats 无法表示账户额度，因此不采用。

将 percent、毫秒 resetsAt 转成现有 UsageRead。复用额度条和手动/定时刷新，60 秒请求间隔、20 秒子进程超时、5 分钟显示有效期。第一版仅展示 Go 额度，标明 Console 工作区来源，routingEligible=false；Console 与 Go Key 的账户归属未经机器验证，不参与自动切换、限额标记或历史预测。预算、充值余额和多账号绑定不在本次范围内。

用量按工作区/location 和非秘密连接元数据区分缓存。切换工作区、连接、无 Console 登录、无 Go 数据时不能继承其他来源额度。查询失败且无法确认来源时清空旧窗口；宁可暂时显示不可用，也不把旧账户数据当成当前账户数据。错误提示不拼接 CLI 原始输出。字段缺失、负百分比、非有限数、非法时间戳应拒绝；超过 100% 的有限读数保留原值，显示组件自行限制条形长度。

验收：单测验证映射、null/缺少 Go、异常输出、CLI 超时和版本隔离；用量合并覆盖来源变化和缓存标记；类型检查和全套测试通过；重载本机插件并验证 RPC。真实账号额度验证需要用户完成 Console 设备授权，同一工作区结果与官方页面对照属于人工验收。
